# Microprice 📈

**[Live demo](https://microprice-virid.vercel.app)**: held-out results, the parameter sweep and a recorded replay

## Project Description 🎨

Microprice is a market-making research platform. A C++20 matching engine simulates a price-time priority limit order book and publishes every book event as a binary ITCH-style feed over UDP multicast. A kdb+/q tick store (with a pandas twin for machines without a kdb+ license) holds the order flow, and Python and R research pipelines turn it into short-horizon signals: the micro-price, order flow imbalance, a LightGBM forecast and FinBERT sentiment on financial headlines. An Avellaneda-Stoikov market maker quotes against those signals inside the engine, so its orders fill by queue position after an order entry latency. Apache Spark sweeps the strategy's parameters, a CVXPY optimizer sets inventory limits across ten stocks, and a React dashboard streams P&L, inventory, fills and the order book over WebSockets. Every published number is regenerated by `make results`.

## Architecture 🏗️

- **Pattern**: event-driven pipeline (engine, feed, tick store, research, strategy, dashboard), with the engine's event sink as a template parameter so no virtual call sits on the hot path
- **State Management**: a single-threaded engine owns each book; the strategy reacts to events and returns quote instructions
- **Concurrency**: a lock-free single-producer single-consumer ring buffer between the feed handler and its writer; Spark for parallel backtests
- **Memory**: preallocated order pool and an open-addressing id map, so matching makes no heap allocation after construction
- **Target**: macOS or Linux, C++20 (Clang 17+ or GCC 13+), Python 3.12, R 4.4+, Node.js 22

```
engine/     C++20 order book, market maker, pybind11 bindings, tests, benchmarks
feed/       wire format, multicast publisher and receiver, replay and capture tools
tickstore/  q schema, loaders, analytics and q unit tests
research/   Python package: data, features, forecasts, backtests, sweeps, gateway
analysis/   R markout and adverse selection analysis
dashboard/  React and TypeScript dashboard
infra/      Docker, Terraform and the EMR sweep script
```

## Features 🌟

- ⚡ **Matching Engine**: price-time priority with limit, market, IOC, cancel and replace orders, checked against a reference book over one million random operations
- 📡 **Multicast Feed**: 48-byte ITCH-style messages with sequence numbers and gap detection
- 🗄️ **Tick Store**: as-of joins, micro-price, order flow imbalance and grid features in q, mirrored in pandas
- 🧠 **Signals**: LightGBM forecasts trained with purged walk-forward splits, and FinBERT headline sentiment
- 🏦 **Market Maker**: Avellaneda-Stoikov quoting with inventory skew, queue-aware fills and order entry latency, in C++ with a Python reference
- 🧮 **Sweeps and Risk**: Spark parameter search with deflated Sharpe ratios, and CVXPY inventory limits
- 📊 **Dashboard**: live P&L split into spread capture and inventory P&L, an order book ladder and result tables, built to WCAG 2.2 AA

## Results 📊

Measured on an Apple M1 (8 cores). The order flow is synthetic, so strategy figures describe the simulation; comparisons between strategies on the same days are the meaningful part.

| Area | Result |
| --- | --- |
| Matching engine | 30M orders per second on one thread, 0 heap allocations per order, p99 167 ns per operation |
| Multicast feed | 262,641 book events over loopback with 0 sequence gaps, p99 one-way latency 240 µs |
| Data | 11.9M order book events across 10 symbols and 5 days, in LOBSTER format |
| Forecast | 10-second information coefficient 0.382 for LightGBM against 0.243 for the micro-price alone |
| Sentiment | FinBERT sign agrees with human labels on 85.5% of 11,480 headlines |
| Parameter sweep | 10,240 parameter sets, 102,400 backtests on Spark in 14 minutes |
| Held-out days | With every other parameter fixed, signals move P&L from −$6,086 to +$10,137 and the 10-second markout from −0.58 to +0.61 ticks per share |

Full figures, with the command behind each one: [docs/RESULTS.md](docs/RESULTS.md) and [docs/BENCHMARKS.md](docs/BENCHMARKS.md).

## Getting Started 🚀

```bash
cd research && uv sync --extra spark --extra nlp && cd ..
make build        # C++ engine, feed tools and the Python module
make test         # C++, Python, R and dashboard tests
make results      # data, headlines, forecasts, sweep, held-out evaluation, analysis, benchmarks
make gateway      # in one terminal
make dashboard    # in another, then open http://localhost:5173
```

The q unit tests run when a `q` binary is on the PATH (`q tickstore/tests/test_analytics.q`), and `tickstore/load.q` builds an HDB from any LOBSTER folder.
